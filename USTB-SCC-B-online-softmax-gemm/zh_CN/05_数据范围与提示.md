## 数据类型

| 参数 | dtype | 字节 |
|------|-------|------|
| `Q`, `K`, `V`, `mask`, `O` | `__nv_bfloat16` | 2 |
| `alpha` | `float`（32-bit） | 4 |
| `B`, `H`, `S`, `D` | `int64_t` | 8 |

## 存储与布局

- 所有 tensor 均为 **连续存储**（contiguous），row-major 布局
- 无需处理 stride 或非连续情况

## 数据范围与场景

| 项目 | 范围或说明 |
|------|-------------|
| `B` | `1 <= B <= 2` |
| `H` | `16 <= H <= 32` |
| `S` | `512 <= S <= 4096` |
| `D` | `64` 或 `128` |
| `mask` | causal mask 或 `nullptr` |

正式测试点全部隐藏。评测会覆盖不同序列长度 `S`、不同 head 数 `H`、`D=64/128`、多 batch、causal mask 和 `mask == nullptr` 两类场景，以及 `S` 不能被常见 tile size 整除的边界场景。参赛者应基于 attention 结构和输入规模特征进行通用优化，不应依赖固定测试点写死实现。

### mask 场景

评测会覆盖 causal mask 和无 mask 两类场景。`mask != nullptr` 时为 causal mask（上三角 `-inf`，下三角和主对角线 `0`）；`mask == nullptr` 时表示无 mask，等价于全零 mask。

## 正确性要求

- 输出与 PyTorch baseline 比较：`torch.allclose(rtol=1e-2, atol=1e-2)`（bf16→float32 后比较）
- 容差考虑了 bf16 精度限制和累加顺序差异
- 所有正式测试点必须全部通过

## 边界条件

- $S$ 可能不是 block tile size 的整数倍，必须处理边界
- $D$ 可能不是 warp tile size 的整数倍（D=64 通常可被 16/32 整除，但实现应具备通用性）
- `mask == nullptr` 时必须正确处理（等价于全零 mask）
- 批量维度 $B>1$ 时需正确处理多维索引

## 约束

- 禁止将中间矩阵 $S$ 和 $P$ 完整写入 HBM
- 禁止修改输入 tensor（`Q`, `K`, `V`, `mask`）
- kernel 启动前不依赖输出 `O` 的初始内容
- 所有测试点在单张 A800 的 VRAM 限制内运行

## 提示

- `cp.async` 可用于将全局内存数据异步加载到共享内存，释放 CUDA core 做计算
- 共享内存双缓冲（double buffering）可有效掩盖数据加载延迟
- `__nv_bfloat162` 可在单个寄存器中打包两个 bf16 值
- online softmax 的数值稳定性：当 $D$ 较大时，点积值可能较大，但本题 $D \le 128$ 且输入值在 $[-1, 1]$ 范围内，bf16 的指数范围（约 $[-9.7, 9.7]$ 在 exp 前）通常不会溢出
- 本题的核心挑战在于**融合**而非单纯的 GEMM 性能——重点考察参赛者对计算-访存重叠的理解
